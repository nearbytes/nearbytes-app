Nearbytes UI specification · methodology

Quiet surfaces. Explicit states. No chrome spill.

This document defines the working rules for the shared Nearbytes UI.

One visible decision at a time

The shell should ask for either a selection, a mode choice, or an action. Never all three at once.

Open implies close

Any sheet, panel, dialog, or takeover view must close using a consistent exit grammar shared across desktop and phone.

Content over controls

Files, chat, identity, and history are the product. Chrome should recede until it is needed.

One scroll owner

Each screen state has one dominant scrolling surface. Nested scrollbars are treated as a design bug unless the surface is a modal takeover.

Method

1
Inventory the surfaces

Use the shared surface inventory as the capability boundary. The redesign may simplify choreography, but it may not silently drop create, join, files, chat, history, identities, storage locations, or reset.

2
Separate state classes

Primary mode, secondary surface, and modal flow must be modeled independently. This prevents accidental toggle collisions and makes close behavior deterministic.

3
Reduce persistent chrome

Keep only hub selection, create, and one overflow handle in the shell. Secondary controls move into a single consistent sheet system.

4
Design mobile first for overflow safety

Phone is the stricter layout. If the shell works at phone width with no horizontal overflow and no double scrollbars, desktop can scale upward cleanly.

5
Review transitions, not just screens

The quality bar is state correctness. Review must ask: what opened, what stayed open, what closed, and how does the user get back?

Design constraints

Shared source rule
Desktop and phone use the same state machine and surface taxonomy. Presentation adapts; semantics do not fork.
Primary shell rule
The shell exposes current hub, current workspace, and current content. Secondary product surfaces live behind a single overflow/sheet system.
Action grammar rule
Selectors select. Buttons act. Switches persist a policy. Tabs or segmented controls change modes. A control must not impersonate another class.
Surface hierarchy rule
Shell → workspace → secondary sheet → modal flow. Deeper surfaces never pretend to be peers of higher ones.
Visual direction Keep the shell quiet, keep the content dominant, and keep every control readable by function.

Control taxonomy

Control class Used for Not used for Nearbytes examples
Selector Change the current hub or current workspace mode Open transient tool surfaces Current hub chooser, Files/Chat/Split switch
Action button Immediate verbs Persisted state or mode ownership Create hub, Share, Join
Overflow handle Reveal secondary surfaces Primary navigation or identity of current state Identities, Timeline, Flow, Locations, Reset
Sheet Temporary secondary product surface with a clear close path Deep modal workflows or primary workspace Storage locations, identities, history, event flow
Modal flow Focused tasks that temporarily interrupt the shell Persistent inspectors Create chooser, join hub, share hub, reset
